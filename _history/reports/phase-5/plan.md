# Фаза 5 — план по 14 замечаниям пользователя

Источник: сообщение пользователя от 14.11.2026 (после отчёта о Фазе 4).
Вердикт Фазы 4 остаётся REJECT до закрытия этих пунктов: они меняют UI и данные,
поэтому доказательства Фазы 4 всё равно устаревают.

Правила прежние: оркестратор не пишет код/не собирает APK/не дёргает adb;
кодеры → `device-qa` → `feature-qa` + `visual-critic` + `code-reviewer` (+ `perf-qa`) → `judge`.
Без эмодзи, без заглушек, всё по-русски, REFS (`refs/`, `refs_src/`) только читать.

## 1. Замечания пользователя (дословно)

1. Фон почти всех тем в ОЧЕНЬ низком разрешении — либо применить блюр к самим фотографиям, либо найти другие.
2. Цены на такси фиксированные и не реалистичные — посмотреть в интернете реальные.
3. При открытии любой функции в навбаре (например «Вид») навбар пропадает.
4. Непонятно, что происходит в рулетках тем; логика интерфейса отвратительна; всё это должно быть в лутбоксах, а не две отдельные рулетки.
5. Свайпы по карточке погоды переключают города без анимации — добавить.
6. В списке городов добавить возможность добавлять свои города.
7. На карточке ЛЮБОГО города пишется «ТЕКУЩЕЕ МЕСТО», хотя это не так.
8. Лутбоксы должны выглядеть как лутбоксы, а не «рандомная хуйня без анимации»: анимации, конфетти и вибрация при выпадении.
9. Реклама всегда одна и та же, снизу просто кнопка покупки премиума без пояснения — так интерфейс выглядеть не должен.
10. График «Осадки» не работает.
11. Убрать упоминание Минска, заменить белорусские рубли на русские.
12. Совет один и не меняется.
13. Зачем у блока с оценкой погоды кнопка «Развернуть».
14. В лутбоксах должны выпадать ВИДЫ погоды по реальному прогнозу: «Поздравляем! Вам выпал дождь на завтра!».

## 2. Решения и раскладка по ролям

### data-coder A — данные, модели, ViewModel (items 2, 6, 7, 10, 11, 12, 14 + 8/9 data)

**11. Валюта и Минск.**
- `BYN` вычищается из UI и моделей: `PremiumOffer`, `UmbrellaItem`, `FlightOffer`, `TaxiRide`,
  `formatByn` (`ui/design/Formatters.kt` — текст функции тоже), `MainWeatherCards` («Зонтики от»),
  `UmbrellaShopDialog`, `FlightBookingDialog`, `TaxiBottomSheet`, тесты.
- Премиум: `179 ₽` (старая `899 ₽`) — это те же 5.99/29.99 BYN по курсу ≈30 ₽, скидка 80 % сохраняется.
  Формат: `priceLabel = "179 ₽"`, `oldPriceLabel = "899 ₽"`.
- Зонтики: `priceRu` уже в рублях (649/990/790/850) — `priceByn` удалить, в витрине и в строке
  «Зонтики от» брать минимум по `priceRu`.
- Билеты: оффер `fl_minsk_msq` (Минск, Белавиа) → `Сочи (AER)`, авиакомпания «Россия»,
  вылет 09:40 / прилёт 12:20, «2 ч 40 мин», цена `6900 ₽`, `weatherAtDestination = "Солнечно, +26"`.
  `priceByn` удалить у всех офферов.
- Города по умолчанию (`WeatherRepository.defaultCities`): Санкт-Петербург, Москва, **Сочи**, Дубай.
  Никаких упоминаний Беларуси/Минска в `app/src/main` и данных (тест на это добавить).

**7. «Текущее место».**
- `CityLocation` += `val isCurrentLocation: Boolean = false` (сериализуемое, с дефолтом).
- `MainScreenUiState` += признак, что выбранный город — текущее место:
  `val isSelectedCityCurrentLocation: Boolean` (или вычисляемое из `selectedCity`).
- `defaultCities[0]` (СПб) помечается `isCurrentLocation = true`; города из поиска — false.
- Заголовок: `ТЕКУЩЕЕ МЕСТО` только для гео-города; иначе `ВЫБРАННЫЙ ГОРОД`
  (решает ui-coder, данные даёт VM). Тест: для добавленного города флаг false.

**10. Осадки.**
- Причина: `HourlyItem.popKnown` для MET Norway всегда `false` → вкладка «Осадки» показывает «—».
- `HourlyItem` += `val precipitationMm: Double? = null`, `DailyItem` += `val precipitationMm: Double? = null`.
- `MetNoForecastParser` уже читает `precipitation_amount` (`next_1_hours`) — прокинуть в
  `HourlyItem.precipitationMm`; `SevenTimerForecastParser` и Open-Meteo — тоже, где есть.
- `precipitationProbability` остаётся как есть (нет у MET — `popKnown = false`).
- Итог для UI: есть мм → график столбиков мм/ч; есть % → подпись; нет ни того, ни другого →
  честное «Нет данных об осадках» (а не пустой ряд).
- Тесты: парсер MET даёт ненулевые мм для часа с дождём; при отсутствии — null.

**2. Такси.**
- `TaxiTariffType` переделать: `minFareRu`, `perKmRu`, `perMinRu`, вместо `basePriceRu/basePriceByn`.
  Значения по официальным тарифам Яндекс Go СПб (максимальные, проверено 14.11.2026,
  `taxi.yandex.ru/spb/tariff/...`):
  - Эконом: минимум 149 ₽ (3 мин + 1 км), далее 12 ₽/км и 12 ₽/мин;
  - Комфорт+: минимум 205 ₽, далее 17 ₽/км и 17 ₽/мин;
  - Ultima (Business): минимум 349 ₽, далее 30 ₽/км и 25 ₽/мин (оценка по Business, помечено в коде).
- Формула: `boarding = minFare`, `duration = 3 + distanceKm * 2.2` мин,
  `price = max(minFare, minFare + 12 * max(0, km - 1) + 12 * duration) * surge`,
  surge = 1.0 + (trafficScore-3).coerceAtLeast(0)*0.12 при наличии пробок, иначе 1.0 (без выдумок).
- `TaxiState` += `val priceByTariff: Map<TaxiTariffType, Int>` и `val durationMinByTariff: Map<...>`,
  пересчёт при выборе точки/тарифа. Старое `basePriceRu` больше не показывать на карточках:
  на каждой карточке цена **для выбранного маршрута** + время в пути.
- `TaxiRide.priceByn` удалить. Тесты: 1 км = минимум; 10 км ≈ 149+108+? по формуле; пробки 0 → без наценки.

**12. Совет/факт.**
- `AiFactsRepository`: факт по умолчанию — детерминированно на календарный день
  (`facts[dayOfYear % size]`), `refreshAiFact()` не повторяет текущий и не листает по кругу
  (сдвиг + случайный из остальных), список фактов расширить до ≥16.
- «Совет на сегодня» (`clothingAdvice` в маппере/WmoHelper): 3+ варианта на температурный
  диапазон с учётом ветра (>8 м/с), осадков (дождь/снег) и солнца; выбор детерминирован
  от `city + dayOfYear`, чтобы не «дёргался» при рекомпозиции, но менялся по дням и городам.
- Тесты: два разных дня → разные факты; повторный refresh не равен предыдущему;
  разные города в один день могут дать разные советы (детерминизм сохраняется).

**6. Добавление города (данные).**
- `removeCity`/`addCity` уже есть; добавить `addCity` из строки поиска и защиту от дублей
  (по имени+координатам). Лимит сохранённых городов не ломать.
- `CityLocation("Сочи", 43.5855, 39.7231, "Россия", "Краснодарский край")` — в каталоге поиска
  не обязателен (Photon найдёт), но в дефолтах есть.

**14. Лутбоксы: погода по реальному прогнозу.**
- `LootRewardType` += `WEATHER_TOMORROW`; `LootReward` += `kind`, `weatherText`, `weatherIconType`,
  `dayLabel` (например «на завтра»).
- `LootboxRepository.openLootbox(forecast)` получает реальный прогноз на завтра
  (`daily[1]` / `daily[0]` если сегодня) и, если выпал погодный приз, формирует:
  - дождь → «Поздравляем! Вам выпал **дождь на завтра**» + иконка дождя,
  - снег → «…выпал снег на завтра», гроза, туман, солнце, облачно — по WMO-коду;
  - есть осадки в прогнозе → вес погодного приза выше (35 %), иначе 15 %.
- Копирайт без эмодзи, «выпал/выпала» согласовать с родом слова (дождь/снег/солнце).
- История дропов: `LootboxRepository.history` сейчас в памяти — сохранять в DataStore
  (`lootbox_history_json`, последние 20) и отдавать в `LootboxState`.
- `LootboxState` += `lastRewardSeq: Int` (растёт при каждом дропе → UI ловит один выстрел
  анимации/вибрации), `history: List<LootReward>`, `isOpening` уже есть.
- Тесты: при прогнозе «дождь» и выпавшем погодном призе текст содержит «дождь на завтра»;
  при отсутствии прогноза погодный приз не выпадает; seq растёт; история переживает перезапуск (фейк-кэш).

**9. Реклама (данные).**
- Новый `data/model/AdModels.kt`: `AdCreative(id, brandRu, headline, body, ctaLabel, action, imageCategory, disclaimer)`
  и `data/repository/AdRepository.kt` с 4 креативами:
  1) курс «Дизайнеры больше не нужны» (AD_LAPTOP) → CTA «Смотреть премиум-условия» (пейволл),
     disclaimer: «Реклама. Курс не связан с разработчиком приложения.»
  2) iPhone 16 Pro Max (IPHONE) → CTA «Открыть лутбоксы» (шанс 0.001 %), disclaimer про рекламу;
  3) «Зонтики от 649 ₽» (нет фото → иконка) → CTA «В магазин зонтов»;
  4) «Яндекс Еда: пицца за 30 минут» (FOOD) → CTA «Открыть Еду», deep link.
- Ротация: `uiState.adCreative` выбирается детерминированно по `dayOfYear + index` (или по
  счётчику открытий), чтобы «всегда одна и та же» не повторялось; переход к следующему
  по кнопке-стрелке не нужен — достаточно смены между сессиями/днями.
- `MainScreenUiState` += `adCreative: AdCreative` и `adImageUrl: String?`.

**Миграции/тесты:** обновить `UiPersistenceContractTest` (BYN → ₽), `MainScreenViewModelTest`

### data-coder B — фоны тем (item 1), только ассеты и маппинг

- 7 тем (`BLUE_SKY`, `COPPER_SUNSET`, `FOREST`, `MARS`, `CYBERPUNK`, `BLOODY_SUNSET`, `AURORA_BOREALIS`)
  получают **локальный** фон в `app/src/main/res/drawable-nodpi/theme_<mode>.jpg`.
- Источник — Wikimedia Commons через API (`action=query&generator=search&gsrnamespace=6&prop=imageinfo&iiprop=url|extmetadata&iiurlwidth=1920`),
  только свободные лицензии (CC0/PD/CC BY/CC BY-SA), реальные фото, без коллажей и текста.
  Обязателен `User-Agent` `KOCHWeather/1.0 (android; +https://github.com/koch/weather)`.
- Обработка локально (Python из `load_workspace_dependencies`, Pillow): скачать ≥1600 px,
  кроп 9:16 по центру → 1080×1920 → `GaussianBlur(radius≈6)` → лёгкое затемнение (−12 % яркости,
  чтобы белый текст читался) → JPEG quality 80. Цель: 120–260 КБ на файл, суммарно ≤1.6 МБ.
- `data/model/ThemeBackgrounds.kt`: `val AppThemeMode.backgroundRes: Int?` (`@DrawableRes`),
  чтобы каждая из 7 тем имела свой фон; без сети и без Coil.
- `ATTRIBUTIONS.md` в корне: для каждого файла — тема, файл Commons, автор, лицензия, ссылка.
- Проверка: `file`/Pillow открывает все 7, размеры 1080×1920, вес в лимите, `res` компилируется
  (`compileDebugKotlin` после того, как ui-coder подключит — или просто `aapt`-проверка через сборку).
- Старые сетевые `ImageCategory.SKY_*` можно оставить (не ломать `ImageCatalog`), но UI перестаёт
  их использовать как фон — это делает ui-coder.

### ui-coder — интерфейс (items 3, 4, 5, 6-ui, 7-ui, 8, 9-ui, 10-ui, 13, 1-ui)

3. **Навбар не пропадает.** Один `Scaffold` на весь `MainScreen`: `bottomBar = KochNavBar`,
   контент — `when(selectedTab)` (HOME/MAP/LIST/SEARCH/THEMES) **внутри** контента Scaffold.
   У `WeatherMapScreen`/`CityListScreen`/`CitySearchScreen`/`ThemeGalleryScreen` убрать кнопку
   «назад» из шапки (навигация — бар), сохранить отступ снизу под бар и `navigationBarsPadding`.
   Тап по активному табу ничего не делает; повторный тап по «Главная» — наверх ленты.
4. **Одна рулетка — внутри лутбокса.** Удалить отдельный `ThemeRouletteDialog` и карточку
   «Рулетка тем» из «Вид»; при выпадении темы в лутбоксе — экран «Поздравляем!» с превью
   телефона и жёлтыми `◀ ▶` (перенести `PhonePreview`/`YellowArrow`/`ThemeTicket` в
   `LootboxDialog`/`LootboxReveal`). Тема применяется кнопкой «Применить», закрытие — «Продолжить».
   Никаких двух входов в одну и ту же механику.
5. **Анимация смены города.** `AnimatedContent` (slide по направлению свайпа + fade, 260–300 мс)
   вокруг шапки/температуры и ленты; направление берётся из `next/prev`. Не анимировать весь
   `LazyColumn` (jank) — только шапку и первые карточки либо `AnimatedContent` на уровне колонки
   контента с `SizeTransform(clip=false)`.
6. **Добавить город из списка.** В `CityListScreen`: кнопка «+» в шапке и строка «Добавить город»
   внизу списка → `onAddCity` → вкладка «Поиск». В поиске каждый результат — «Добавить»/«Уже в списке».
8. **Лутбокс как лутбокс.** Закрытый сундук (объёмный, без «иконки в ореоле»): тап → тряска
   (scale/rotate keyframes ~700 мс) → вспышка → конфетти (`Canvas`, 60–90 частиц, 1.2 с) →
   карточка приза с цветом редкости, свечением и `HapticFeedback`/`Vibrator`
   (`VibrationEffect.createOneShot(35, DEFAULT_AMPLITUDE)`, permission `VIBRATE` уже в манифесте —
   проверить). Анимация стартует от `lastRewardSeq`. Никаких «пустых» состояний без объяснения.
9. **Реклама.** Баннер и лист рисуют `uiState.adCreative` (заголовок/боди/CTA/disclaimer),
   CTA ведёт в соответствующую функцию (пейволл/лутбоксы/зонты/еда). Под CTA — мелкий
   текст «Реклама. …» и вторичная ссылка «Отключить рекламу — Премиум 179 ₽/год».
   Никакой кнопки «Подписка Премиум» без пояснения.
10. **Осадки.** Вкладка «Осадки»: столбики мм/ч по часам (`Canvas`, высота по max мм),
    подпись «Осадки, мм/ч»; если мм нет, но есть % — показывать %; если нет ничего —
    «Нет данных об осадках» с причиной. Никаких «—» на весь ряд.
13. **Оценка погоды.** Убрать «Развернуть/Свернуть» и скрытый блок; оставить среднюю оценку,
    звёзды и подпись, без кнопки-обманки.
7-ui. Заголовок города: `ТЕКУЩЕЕ МЕСТО` только при `isSelectedCityCurrentLocation`,
   иначе `ВЫБРАННЫЙ ГОРОД`.
1-ui. `KochSkyBackground` принимает `@DrawableRes imageRes` (локальный фон темы) и рисует его
   через `Image(painterResource(...))`; сетевые `sky*ImageUrl` больше не используются как фон
   (предзагрузку в `MainScreen` убрать). В галерее тем — превью локального фона.

## 3. Definition of done Фазы 5

1. `compileDebugKotlin` + `testDebugUnitTest` зелёные (≥160 тестов), отчёты кодеров файлами.
2. `device-qa`: `assembleDebug` + `assembleBenchmark`, install, `logcat`, свежие `shots/r14_*`
   по всем 14 пунктам (навбар на «Вид», анимация свайпа, добавление города, «ВЫБРАННЫЙ ГОРОД»,
   лутбокс с конфетти, реклама двух разных креативов, осадки с мм, такси с ценами по маршруту,
   фон темы, отсутствие BYN/Минска, оценка без «Развернуть»).
3. `visual-critic` PASS по новым кадрам, `feature-qa` PASS по сценариям, `code-reviewer` PASS,
   `perf-qa` — jank не хуже (фон-фото локальный, конфетти только в листе).
4. `judge` PASS → отчёт пользователю с APK, `shots/`, логами.
5. Коммит `Phase 5: ...` после PASS.
