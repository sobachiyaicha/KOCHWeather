## 8. Лутбокс как лутбокс (+ конфетти и вибрация)

- **Закрытое состояние**: `ChestCanvas` рисует объёмный сундук (корпус с градиентом дерева,
  три металлические полосы с бликами, обод, пластина замка со скважиной и язычком, блик на
  корпусе и крышке). Под ним — пульсирующий ореол `ChestGlow` (radial gradient, 1.4 с reverse).
  Подписи: «Сундук Утешения #2025», «Шанс на iPhone 16 Pro Max: 0.001 %».
- **Открытие** (`LaunchedEffect(lootboxState.isOpening)`): тряска 700 мс — поворот
  `sin(progress·6π)·4°` (±4°), масштаб `1 + 0.06·sin(progress·π)` (1→1.06→1); затем крышка
  поворачивается на −40° вокруг петли (240 мс), появляется свет из щели и вспышка
  (70 мс вверх / 300 мс вниз). Текст меняется на «Сундук открывается...».
- **Дроп** (`LaunchedEffect(lootboxState.lastRewardSeq)`): ровно один выстрел на дроп — вибрация,
  конфетти 72 частицы цвета редкости (гравитация `p²`, 1.2 с, затухание на последних 28 %),
  затем карточка приза. Гард `seenSeq`: повторный вход в лист с уже полученной наградой
  **не** переигрывает анимацию/вибрацию (рекомпозиция тоже не переигрывает).
- **Вибрация**: API ≥ 31 — `VibratorManager.defaultVibrator`; API ≥ 26 —
  `VibrationEffect.createWaveform(longArrayOf(0, 40, 60, 40), -1)`; ниже — `vibrate(120)`.
  Проверка `hasVibrator()`; разрешение `VIBRATE` добавлено в манифест.
- **Карточка приза**: свечение и рамка `Color(rarity.colorHex)`, крупная иконка (погода — по
  `weatherCode` через `WmoHelper.getIconType`, тема — `Palette`, iPhone — `PhoneIphone`, зонт,
  сапоги, кофе), `rarity.titleRu`, `title` (погодный приз приходит готовым: «Поздравляем! Вам
  выпал дождь на завтра»), `subtitle`, для погоды — иконка + описание WMO + `temperatureRangeRu`.
- **Кнопки без обмана**: у приза-темы — «Применить» (или «Применена», если тема уже текущая;
  всё равно вызывает `onApplyTheme`), у остальных — «Продолжить» (закрывает лист).
- **История**: `lootboxState.history.take(5)`, полоска цвета редкости + название + редкость;
  пусто → `KochEmptyState` «Вы ещё не открывали сундуки» / «Нажмите «Открыть бесплатно» —
  призы появятся здесь».
- CTA футера — «Открыть бесплатно», в состоянии `isOpening` крутит `loading` и заблокирована.

## Открытые вопросы

1. **VM сам применяет выпавшую тему** (`openLootbox`: `currentTheme = newTheme`). Поэтому сразу
   после дропа темы экран показывает «Применена», а «Применить» работает как подтверждение
   (идемпотентно). Если нужно «выпала, но ждёт кнопки» — это одна строка в
   `MainScreenViewModel.openLootbox` (зона `data-coder`), UI к этому готов.
2. **Ветер в совете дня**: `DailyDetailDialog` принимает `windSpeedMps: Double? = null`;
   `MainScreen` его не передаёт (по договорённости файл не мой). Совет всё равно меняется
   по городу/дню; чтобы учитывать ветер — передать `uiState.weather?.windSpeed`. `dayOfYear`
   по умолчанию вычисляется внутри (`currentDayOfYear()`), вызов править не нужно.
3. **Манифест**: `VIBRATE` добавлен — при `assembleDebug` стоит глянуть merged manifest
   (нужен только для вибрации дропа, runtime-запроса не требует).

## M1. Вспышка лутбокса больше не залипает — `ui/components/LootboxDialog.kt`

- `LaunchedEffect(lootboxState.isOpening)`: тряска 700 мс → **параллельно** крышка 240 мс и
  вспышка 70 мс вверх + 220 мс вниз через `coroutineScope { launch { ... } }`. Итого
  **990 мс < 1200 мс**, за которые VM отдаёт награду и гасит `isOpening` (раньше
  700 + 240 + 70 + 300 = 1310 мс, и отмена на 1200-й оставляла `flash` ≈ 0.2–0.4).
- Вся последовательность обёрнута в `try/finally`; в `finally` —
  `withContext(NonCancellable) { flash.snapTo(0f) }`, поэтому отмена эффекта (дроп или
  закрытие листа) физически не может оставить ненулевой блик.
- `LaunchedEffect(lootboxState.lastRewardSeq)`: перед вибрацией/конфетти добавлены
  `flash.snapTo(0f)` и `shake.snapTo(1f)` (в дополнение к `lid.snapTo(1f)`), то есть дроп
  гасит блик даже если эффект открытия был отменён на середине.
- Блик рисуется только при `flash > 0.01f`; после дропа и после закрытия листа `flash == 0f`.
- Заодно убран единственный warning компилятора: `Icons.Filled.DirectionsWalk` →
  `Icons.AutoMirrored.Filled.DirectionsWalk` (L7). В `app/src/main` предупреждений больше нет.

## M2. «Другой факт» достижим — `ui/main/MainCards.kt`, `ui/main/MainScreen.kt`

- `AiFactCard` получил явную кнопку-строку **«Другой факт»** под текстом факта:
  `Icons.Default.Refresh` + `KochType.caption` в капсуле, `Role.Button`. Дополнительно весь
  блок кликабелен (`combinedClickable`) — тап по факту тоже даёт новый факт.
- `MainScreen.kt`: `AiFactCard(onClick = onRefreshAiFact, ...)` — открытие модалки травы из
  этого блока убрано. `MainScreenViewModel.refreshAiFact()` → `getNextFact(uiState.aiFact)`
  вызывается из UI, параметр `onRefreshAiFact` больше не мёртвый.
- **Модалка травы (R11) осталась достижимой**: у VM нет таймера «слишком долго смотрели
  погоду», и `onOpenGrassModal` больше нигде не вызывается, поэтому он повешен на
  **долгое нажатие** по тому же блоку факта (`onLongClick`). Обычный тап = новый факт,
  long-press = блокировка «Пора на улицу!». Это компромисс без правки VM; см. открытый вопрос 1.

## M4. Память галереи тем — `ui/components/ThemeVisuals.kt`

- Новый `ThemePreviewImage`: `BitmapFactory.decodeResource(..., Options().apply { inSampleSize = 4 })`
  → 270×480 (≈ 0.5 МБ) вместо 1080×1920 (≈ 8.3 МБ). Битмап берётся из `LruCache<Int, ImageBitmap>`
  (8 записей) и запоминается через `remember(resId)` — на рекомпозицию и на скролл сетки
  заново не декодируется и не пересоздаётся.
- Используется во всех превью: карточки «Вид» (`ThemeGalleryScreen`), мокап телефона и
  билеты (`LootboxReveal`). Полный ресурс остался только у полноэкранного фона
  (`KochSkyBackground` → `painterResource`) — как и требовалось.
- 7 тем: было ~58 МБ декодированных битмапов, стало ~3.6 МБ. При ошибке декодирования —
  фолбэк на полный ресурс/градиент темы (пустых плашек нет).

## График осадков: ось и подписи

Правка по FAIL `visual-critic` (M4, кадр `shots/r14_10_rain_chart.png`). Файлы:
`ui/main/MainWeatherCards.kt` (`PrecipitationChart`), `ui/design/Formatters.kt`,

**Что заменено.**

1. **Подписи осей привязаны к слотам.** Подпись часа рисуется внутри того же Canvas и
   по тому же `slot`, что и столбик: `x = startX + index * slot + (slot - textWidth) / 2`,
   крайние прижимаются к кромке. Сетка осталась «каждый третий час», но это ровно
   `3 * slot` и индексы 0/3/6/…, а не равномерная раскладка по ширине. Дополнительно
   подписываются все часы с осадками (> 0 мм) — «подпись под ненулевыми часами» из M4.
   Коллизии решаются в пользу данных: час с осадками ставится первым, сеточная подпись,
   которая встаёт ближе 2 dp, пропускается. Широкое «Сейчас» (≈33 dp) по-прежнему
   перекрывает соседний слот 1 — его подпись осознанно пропускается, остальные часы свои
   подписи сохраняют.

2. **Y-ось.** Слева появился жёлоб шкалы: на верхней линии — «мм» и максимум («2,5»),
   на нулевой — «0»; обе линии сетки горизонтальные (alpha 0,18 / 0,12). Ширина жёлоба =
   ширина «мм» + 8 dp + ширина подписи максимума + 4 dp, поэтому подписи оси не налезают
   ни на столбики, ни друг на друга. Столбики рисуются строго правее жёлоба.

3. **Плотность.** Высота Canvas = 92 dp при максимуме < 1 мм и 104 dp при значимых
   осадках (≥ 1 мм). Полосы: 14 dp сверху под «мм», 18 dp снизу под часы, остальное —
   область столбиков; при 92 dp это ≈ 60 dp рабочей высоты вместо прежних 104 dp
   пустой рамки. Верх шкалы = реальный максимум, но не ниже 0,1 мм.

4. **Крайние случаи.** Все нули → прежний компактный `NoRainExpected` (не менял);
   один пик → столбик на всю шкалу, подпись одна; 24 часа через полночь → подписи берутся
   из `hourLabel`, «00» и далее встают в свои индексы; `max == 0.1` → шкала «0,1»,
   компактная высота, столбик не исчезает (минимум 2 dp); `null` в `precipitationMm`
   по-прежнему не рисуется и не участвует в максимуме/сумме.

5. **Русский формат.** Десятичный разделитель — запятая: `formatMmRu` вынесен в
   `ui/design/Formatters.kt` (`String.format(Locale.US, "%.1f").replace('.', ',')`),

content-лямбда **игнорировала параметр** и читала `uiState.weather` / `uiState.selectedCityIndex`
из замыкания. Оба слоя (выходящий и входящий) при каждой рекомпозиции перерисовывались из
текущего `uiState`, то есть оба показывали новый город — ровно то, что на кадрах
`r14_03_swipe_a` (обе капсулы «ВЫБРАННЫЙ ГОРОД / Москва») и `_b` (обе «ТЕКУЩЕЕ МЕСТО /
Санкт-Петербург»). Это же ловит lint-правило Google `UnusedContentLambdaTargetStateParameter`:
лямбда обязана быть функцией от параметра.

**Правка.** Анимируется снимок данных города, а не индекс:

- `private data class CitySnapshot(index, weather, citiesCount, isCurrentLocation)` и
  `private data class HourlySnapshot(index, weather, selectedSegment, userRating,
  averageRating, showRatingThankYou)` — в `MainScreen.kt`.
- Снимки считаются в composable-скоупе `MainScreenContent` (content-лямбда `LazyColumn`
  не композируемая, `remember` внутри неё недоступен) через
  `remember(weather, selectedCityIndex, cities.size, isSelectedCityCurrentLocation) { … }`.
- `AnimatedContent(targetState = citySnapshot, contentKey = { it.index }, …) { snap -> … }` —
  `GoldenCapsuleHeader` получает `snap.weather/index/citiesCount/isCurrentLocation`, то есть
  выходящий слой держит **прежний** город, входящий — **новый**. Аналогично
  `HourlyWeatherCard` рендерится из `HourlySnapshot`.
- `contentKey = { it.index }`: обновление прогноза того же города (refresh, кэш)
  перерисовывает слой без слайда; слайд — только при смене города. Раньше поведение было
  таким же (targetState — индекс).
- `transitionSpec` не менялся: те же 280 мс, тот же слайд `width/4` в нужную сторону, тот же
  `fadeIn/fadeOut`, `SizeTransform(clip = false)`. Функция стала generic по получателю
  (`indexOf: (T) -> Int`) плюс два тонких адаптера `cityHeaderTransition()` /
  `cityHourlyTransition()`; **значения анимации не тронуты**. Имена разные, а не
  перегрузки: две перегрузки по `AnimatedContentTransitionScope<CitySnapshot|HourlySnapshot>`
  дают одинаковый JVM-дескриптор (platform declaration clash) — ловилось компилятором.
- Геометрия шапки (`rotate(-15°)`, `offset(-12, -24)`) не тронута.

**Что должно быть на новых кадрах (середина перехода, ~140 мс после свайпа):**
выходящий слой — «ТЕКУЩЕЕ МЕСТО / Санкт-Петербург», входящий — «ВЫБРАННЫЙ ГОРОД / Москва»;
в карточке условий так же: старый почасовой ряд уезжает, новый приезжает. Кадр следует
снимать через `screenrecord`, а не по одному `screencap` (иначе тайминг 280 мс не поймать).

## 2. История дропов уходила под CTA

**Что было.** `r14_15d_history`: видны «История дропов / Открыто: 50» и срез первой
карточки, строк нет — они были ниже кромки листа, а лист стоял на своём максимуме.

**Арифметика листа (1080×1920, плотность ~2.95, экран ~651 dp).** Лист `0.88` = 573 dp,
из них шапка-грабер 12 dp и футер (CTA 52 + паддинги + инсет навбара) ~95 dp → видимое поле
контента ~466–480 dp. Контент же был ~740 dp: шапка 40 + сундук 206 + подписи 36 + карточка
приза 126 + заголовок истории 37 + 5 строк по 47 + паддинги. То есть ~270 dp (все 5 строк
с запасом) физически не могли попасть на экран — отсюда «строк нет».

**Правка (`LootboxDialog.kt`, высоты отданы истории, а не наоборот):**

- `maxHeightFraction` 0.88 → **0.94** (+~40 dp под историю; верх листа на 1080×1920 — 39 dp,
  ниже статус-бара).
- герой-зона сундука 206 → **124 dp** (ореол 208×118, сундук 142×118 — пропорции 1.12
  сохранены, сундук остаётся объёмным);
- карточка приза: вертикальные паддинги 12 → 8, иконка 56 → 44 dp, `maxLines` 3 → 2,
  отступ до кнопки 8 → 4, кнопка 36 → 32 dp;
- строки истории: вертикальный паддинг 8 → 4 dp (−8 dp на строку, 5 строк = −40);
- заголовок истории: верхний отступ 12 → 8 dp;
- **добавлен нижний отступ контенту** (`Spacer(KochSpace.s)` после последней строки, поверх
  штатных 24 dp `KochSheet`) — последняя строка не прилипает к CTA и к градиентной шторке;
- контент листа остаётся скроллируемым (`KochSheet` → `verticalScroll`), CTA — отдельный
  сиблинг ниже области скролла, поэтому **кнопка контент не перекрывает** ни при каком
  размере контента.

Итого контент ~578 dp против ~505 dp видимого поля: шапка, сундук, карточка приза,
заголовок истории и **3 строки** видны сразу, 4–5-я — одним коротким свайпом внутри листа;
при прокрутке до конца все 5 строк стоят выше CTA (это и есть проверка «история видна
целиком над футером»).

**Честно про «5 строк сразу».** На 1080×1920 все пять строк одновременно с сундуком и
карточкой приза не помещаются ни при каком разумном дизайне: шапка 40 + сундук 124 +
подписи 36 + приз 116 + заголовок 33 + 5 строк 211 + паддинги 44 + грабер 12 + футер 95 =
711 dp при экране 651 dp. Уложить это можно только убрав сундук или карточку приза, то есть
сломав проверенный «лутбокс как лутбокс». `visual-critic` сам предложил «кадр со списком
истории (прокрутка листа)» — этот путь и реализован: прокрутка работает, снизу ничего не
обрезается.
**Что снять device-qa:** (а) лист сразу после открытия — видно, что строки есть;
(б) тот же лист после одного свайпа вверх внутри контента — все 5 строк над CTA
(проверка M2b «…облачная погода на завтра» целиком в строке истории). Дополнительно: после
перезапуска приложения `lastReward` не восстанавливается, карточки приза нет — тогда все
5 строк видны и без прокрутки.

## D-1 (блокер) — клавиатура накрывала нижний навбар на «Поиске»

**Причина.** `MainActivity` вызывает `enableEdgeToEdge()`, манифест — `adjustResize`. При
edge-to-edge окно больше не сжимается клавиатурой: IME рисуется поверх контента, а
`Scaffold.bottomBar` (навбар) оставался на своей нижней позиции — под клавиатурой. Тап
«в зону бара» физически попадал в IME/поле и печатал (в отчёте — «Moscow,»).

**Правка** (`ui/main/MainScreen.kt`, `Scaffold.bottomBar`):

```kotlin
.windowInsetsPadding(WindowInsets.ime.union(WindowInsets.navigationBars))
```

- Бар поднимается ровно на высоту клавиатуры и остаётся видимым и нажимаемым; при закрытии
  IME анимированно возвращается.
- `union` берёт максимум из IME и навбара, а не сумму → нет двойного отступа и «прыжка»
  бара, когда IME уже включает системный инсет (прежний `navigationBarsPadding()` убран).
- `Scaffold` пересчитывает `innerPadding`, поэтому контент вкладки (поле поиска сверху и
  список результатов) сжимается по высоте и **не перекрывается** ни баром, ни клавиатурой;
  `bottomContentPadding` для ленты/вуали приходит из того же `innerPadding`.
- Навбар не скрывается (item 3 — бар есть на всех вкладках), а просто поднимается.
- Диалоги (еда/такси/листы) живут в собственном окне и свои IME-инсеты не транслируют в
  activity, поэтому поведение основного навбара там не меняется.

## D-3 (low) — тело рекламного баннера обрывалось «…Достав…»
