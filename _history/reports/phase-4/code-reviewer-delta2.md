## 2. `44bc6d6` → `2874e18` — как коммит FAIL, на HEAD PASS

**Что было в `44bc6d6`:** `TaxiBottomSheet.kt@44bc6d6:157-169` — обычный `Row` вместо `LazyRow`,
при этом `TariffCard` остался с `.width(112.dp)` (`:241`). Комментарий `:154-156` считал
`3×112 + 2×8 = 352 dp при доступных 353` — неверно: 460 dpi даёт экран 375.7 dp, content-width
листа = 375.7 − 2×20 = **335.7 dp** (2× `KochSpace.xl`).

**Следствие.** `Modifier.width` (в отличие от `requiredWidth`) зажимает размер во входящие
constraints, поэтому третья карточка не уезжает за content-edge, а измеряется в
`335.7 − 112 − 8 − 112 − 8 = 95.7 dp` вместо 112. Итог: карточки в строке **неравные**
(112/112/95.7), внутренняя ширина третьей 71.7 dp; цена при `maxLines = 1` начинает резаться
уже при `fontScale ≳1.3`. На 320 dp content = 280 dp, и третьей карточке остаётся
`280 − 112 − 8 − 112 − 8 = 40 dp` (16 dp внутри) — текст гарантированно нечитаем. Это major:
фикс `weight/widthIn` или возврат `LazyRow` был обязателен.

**Текущий HEAD (`2874e18`, файл тот же):** `TaxiBottomSheet.kt:162-168` — `modifier = Modifier.weight(1f)`;
в `TariffCard` (`:236-247`) фиксированной ширины больше нет; цена `:282` и BYN `:288` получили
`maxLines = 2`, eta `:274` осталась `maxLines = 1`. Арифметика: (335.7 − 2×8) / 3 = **106.6 dp**
(внутри 82.6); на 320 dp — 88 dp (внутри 64), тексты переносятся. Деления на ноль нет: сумма
весов = 3 (константа), на 320 dp под веса остаётся 264 dp — падения/overflow при узком экране
не будет. **PASS.**

Nit (не блокируют): (а) устаревший комментарий `:154-156` всё ещё про «352 при 353» —
противоречит `weight`; (б) неиспользуемые импорты `LazyRow`/`items` — `:16-17`; (в) при переносе
заголовка высоты карточек могут разойтись (`Row` без `IntrinsicSize`) — проверить на новом кадре.
