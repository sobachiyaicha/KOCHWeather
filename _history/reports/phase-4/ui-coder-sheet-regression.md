# Регресс: «шторка лутбоксов не открывается» (run 9)

**Дата:** 14.11.2026. **Сборка:** `compileDebugKotlin` → **BUILD SUCCESSFUL in 8s**, 0 warnings
(`.local/build_revert_sheet.txt`).

## Что показывает доказательство
`shots/r9_06_lootbox_FAIL_sheet_not_opened.png` — **шторка открыта и полностью отрисована**
(заголовок, сундук, «История дропов», «Вы ещё не открывали…», синяя CTA). Значит клик по карточке
«Лутбоксы» работает, `onOpenLootbox` доходит, `KochCard.clickable` не потерян — правка
`ServicesGrid` (IntrinsicSize → `heightIn(132)`) ни при чём.

## Настоящая причина — моя перф-правка «контент листа на следующем кадре»
В `KochSheet` был добавлен `contentReady` (`withFrameNanos` → `true`). В результате **первый кадр
листа рисовался без контента**: оставались только граббер и CTA, и высота шторки была ~180 dp
вместо ~700 dp. Дальше сценарий в автоматизации объясняет «три дампа — главная»:

1. тап по карточке → лист открывается **коротким** (один кадр);
2. через ~16 мс контент появляется, но следующий тап (790×1460) попадает **в скрим** — лист
   закрывается (`dismissOnClickOutside = true`);
3. дампы снимались сразу после тапов, поэтому каждый раз показывали главную;
4. последний тап снова открыл лист — это и попало в `r9_06`.

## Фикс
`ui/design/KochSheet.kt` — отложенная композиция **убрана**:
```kotlin
// было
var contentReady by remember { mutableStateOf(false) }
LaunchedEffect(Unit) { withFrameNanos { }; contentReady = true }
if (contentReady) { Box(weight…) { контент } }
// стало
Box(modifier = Modifier.weight(1f, fill = false).fillMaxWidth()) { контент }
```
Диалог и весь контент снова появляются **в одном кадре**, площадь скрима сразу равна целевой,
повторный тап попадает в лист, а не в затемнение. Инсеты, высота, CTA и фейд-кромка не менялись.

## Что проверено
1. `Modifier.clickable` у `ServiceCard` — на `KochCard` (тот же узел, что и раньше); модификатор
   карточки `weight(1f).heightIn(min = 132.dp)` только задаёт минимальную высоту, кликабельная
   область = весь бокс карточки.
2. Карточки в ряду без IntrinsicSize получают одинаковую минимальную высоту 132 dp; область
   тапа совпадает с видимой (никаких внешних `Box` с правилом клика вокруг ряда нет).
3. «Путешествия», «Такси», «Еда» — те же `ServiceCard` и те же `onClick`, изменений нет.
4. Отложенность в `KochSheet` удалена полностью — окно и контент показываются сразу.

## Перф-компромисс
Первый кадр листа снова стоит столько же, сколько до оптимизации (в perf-qa это был худший
случай, 150–200 мс). Остальные перф-правки сохранены: убраны IntrinsicSize, строки дней без
лишних composable, предзагрузка фото неба, кэш `loadedByUrl`.

## Рекомендация для повторного прогона
Тап по карточке → пауза 300–400 мс (окно диалога успевает получить фокус) → дамп. Дамп нужно
снимать с активного окна диалога; если `uiautomator dump` берёт окно активити, он покажет
главную даже при открытом листе — в этом случае проверять по скриншоту.
