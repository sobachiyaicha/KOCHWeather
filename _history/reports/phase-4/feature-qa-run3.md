### 2.3. Исчезновение баннера — **дефект**
Сценарий:
1. 05:52 — приложение оффлайн, баннер `Сохранённый прогноз, 05:43` (fq3_40).
2. ~05:55 — включаю Wi-Fi и данные (`svc wifi enable`, `svc data enable`),
   `Active default network: 232`.
3. 05:55–05:56 — баннер исчезает, но:
   - `weather_cache.preferences_pb` mtime и `lastUpdated` **не меняются** (05:43:26);
   - футер при этом честно пишет: `MET Norway: данные из кэша (обновление не чаще 30 мин).`
   — `shots/fq3_46_online_back.png`, `shots/fq3_47_no_banner_cache_footer.png`,
   `shots/fq3_48_footer.png`, дампы `fq3_ui53.xml`, `fq3_ui55.xml`.

Причина (проверено по коду установленной сборки `f0f2b94`):
`MetNoCachePolicy.shouldUseCache` при кэше моложе 30 мин (Скандинавия) → `WeatherRepository`
возвращает `WeatherLoadResult.Live` из DataStore **без сетевого запроса**; ViewModel ставит
`weatherState = LIVE`, а баннер рисуется только для `CACHED`. То есть баннер скрывается при
повторном чтении кэша, а не после успешного обновления — прямое нарушение критерия
«исчезновение только после успешного обновления». Данные при этом не выдумываются
(футер раскрывает кэш), но семантика баннера неверная.

**Вердикт R19: FAIL** (кэш и отображение баннера — PASS; условие скрытия — FAIL).
Дефект может быть затронут коммитом `b9b6dc8` (race providers / persist state) — перепроверить
после установки run 4.
